基本设置

触发方式决定机器人什么时候把回复转成语音；默认风格是合成时使用的音色（风格 ID 可在安装向导或引擎的 /v1/speakers 中查看）。

引擎连接

COEIROINK 引擎是一个本机 HTTP 服务（默认 127.0.0.1:50032）。留空的路径项会依次从环境变量与常见安装位置自动推导，通常无需填写。

内存与文本限制

引擎推理很吃内存：风格一旦加载就常驻内存，并发合成会成倍放大峰值。内存紧张的机器建议保持「最大并发合成数 = 1」并按需调低缓存条数；下方「缓存」相关项与长期保留池共同决定复用效果。

安全

默认只允许连接本机回环地址的引擎，避免回复内容被发送到外部主机；确需连接远程引擎时再逐项放开。

音频与翻译

控制输出音频格式与「非日语回复」的翻译方式：always_translate 模式下会先用下方系统提示词把文本翻译成日语再合成。

缓存治理（长期保留池）

语音合成很费 CPU（同一句话约 1~8 秒），所以插件会把合成过的音频按复用价值分层保存， 既能秒回常用台词，又不会让长期对话把磁盘占满。

  1. 临时缓存：刚合成的音频，放在系统临时目录，2 小时后自动删除。
  2. 长期保留池：被反复使用的片段晋级到这里，默认保留 30 天，不受临时清理影响。
  3. 超长期保留池：最常用的片段，默认保留 365 天，几乎不会因清理而重新合成。

谁晋级由两步决定：先把所有片段按「调用次数」排序（排序算法即下面的权重项）， 满足 ①排名前 X 或 ②调用次数 ≥ Y（两个条件满足任意一个即可）→ 进入超长期池； 其余达到「晋升门槛」的片段 → 进入长期池。 若复审时有可用的对话模型，则由模型在算法建议的基础上做最终决定（提升层级 / 纳入 / 淘汰）； 模型不可用时完全按排序算法的结果处理，没有 LLM 也能正常治理。 两层各自有容量上限与保留期，超出后按「权重最低、最久未用」优先淘汰。

① 排序权重与晋级条件
决定谁排在前面：纯调用次数只按被复用的次数排名；加权模式会让「长文本且被多次复用」的片段更靠前（省下的合成时间更多）。
排名进入前 X 名即进入超长期池，默认 8；填 0 表示不使用该条件。
被复用次数达到 Y 次即进入超长期池，默认 10；填 0 表示不使用该条件。与条件①是「或」关系。
被复用次数达到该值才进入长期池候选，默认 3。命中次数只有 1~2 次的一次性语音不会被保留。
② 容量与保留期
长期池最多保留多少条音频，默认 64；超出时淘汰「权重最低、最久未用」的条目。
多少天未被使用就回收，默认 30；填 0 表示永久保留（不建议）。
超长期池最多保留多少条，默认 32。这是控制磁盘占用的第二道闸门。
超长期池条目多少天未被使用就回收，默认 365；填 0 表示永久保留。
③ 开关与复审
后台每隔多久重新排名并调整两层池的内容，默认 24 小时；也可以随时在「监控 → 复审缓存池」手动触发一次。

2下载引擎

Windows（CPU 版）
官方下载页：https://coeiroink.com/
BOOTH（シロワニさんのソフトウェア屋さん）：https://booth.pm/zh-tw/items/3436565
Linux / macOS（CPU 版）
官方下载页选择对应系统版本：https://coeiroink.com/
Linux 压缩包解压后目录形如 COEIROINK_LINUX_CPU_v.2.13.0，内含 engine/engine。
通用注意事项
  • 解压后，找到包含 engine/engine（Windows 为 engine/engine.exe）的那一层目录，它就是要填到下一步的「引擎目录」。
  • 完整引擎约 2.7GB，请确保磁盘空间充足（上方自检可查看剩余空间）。
  • 引擎对每个风格懒加载且常驻内存（单份约 2G+），小内存机器建议只用一种风格。
  • Windows 若无 ffmpeg，可用 winget install ffmpeg 安装；Linux 可用 apt install ffmpeg。
